# Смена — веб-версия

Обучающая игра про отладку в большой корпоративной ИТ-среде. Команды по три человека
(менеджер, разработчик, тестировщик) разбирают инциденты завода минеральных удобрений.
Одна мысль на всю игру: **прежде чем чинить, надо спросить** — у кого сломалось, где,
с каких пор, что изменилось.

Vue 3 + Vite на клиенте, Node + WebSocket на сервере. Состояние партии на сервере,
у каждой роли свой экран и свои решения.

## Три страницы

| Кто | Адрес | Что там |
|---|---|---|
| Игроки | `/` | Код занятия, имя, роль, игра |
| Табло (проектор) | `/#/board` | На весь экран без прокрутки: таймер, команды по местам, шаги, лидерборд |
| Ведущий | `/#/host` | Пароль, старт, таймер, раунды, логи команд |

Пароль ведущего по умолчанию `smena`, задаётся переменной `SMENA_HOST_PASS`.
С главной страницы на экран ведущего попасть нельзя — только прямой адрес.

## Как устроено занятие

Занятие — рабочая неделя: разминка и пять дней, Понедельник — Пятница.

1. **Разминка** — один простой инцидент, очки не считаются: команды понимают механику
   целиком, вместе с модулем и деплоем.
2. **Пять дней.** У каждого дня своя тема (после выходных, данные и интеграции, люди
   и доступы, инфраструктура, авралы перед выходными) и пул из пяти инцидентов.
   **Команда играет не все, а свои два** — у соседей задачи другие, тема одна.
3. Инцидент — **пять решений по кругу разработки**: менеджер принимает заявку и ставит
   задачу → разработчик делает → тестировщик проверяет и возвращает с замечаниями →
   разработчик доделывает → менеджер закрывает перед бизнесом. У каждого шага **три
   варианта**. Ходить за чужую роль нельзя.
4. Заявку разработчик и тестировщик видят в той формулировке, которую выбрал менеджер.
5. Закрытый инцидент даёт **модуль** — конкретное решение («Монитор сроков
   сертификатов», «Честная очередь замеров»). В решениях тестировщика и разработчика
   прячется **изъян**, если проверяли для галочки или закрыли костылём. Команде изъян
   не показывают.
6. **Конец дня: менеджер выбирает один модуль** из закрытых инцидентов — тот, в котором
   уверен. Ведущий жмёт «Запустить деплой»: модуль без изъяна уходит в продакшн (+20
   очков), модуль с изъяном **падает** с названной причиной и стоит **−1 доверия**.
7. Не хватило минут смены — **день провален**: модули не внедряются, доверие −2.
   Бюджет минут посчитан так, что до нуля команда доходит только выбирая всё самое
   дорогое; одно разумное решение уже даёт запас.
8. Не успели по реальному таймеру — незакрытые заявки сгорают, доверие −1.
9. По итогам дня все видят **лидерборд**: он раскрывается снизу вверх, от последнего
   места к первому.

## Очки

Все метрики сходятся в одну цифру, по ней и место в лидерборде:

| За что | Сколько |
|---|---|
| уточнение (менеджер сначала спросил) | +10 |
| доверие бизнеса | ×5 |
| модуль в продакшне | +20 |
| каждые 25 минут запаса | +1 |

Доверие ходит **от −10 до +10**: в минусе бизнес перестал верить, и на табло это
видно красным. Веса меняются в `RULES.score`.

### Два времени: таймер и запас минут

Их правда два, и они про разное:

- **Таймер дня** (6 минут, тикает по-настоящему) держит темп занятия: все команды идут
  синхронно, не успел — день закрывается, недоигранные заявки сгорают, доверие −1.
- **Запас минут** — игровая цена решений. Побежал на площадку −30, спросил в чате −5.
  Бюджет выдаётся под конкретный набор инцидентов команды и посчитан так, что ноль
  достигается только при всех самых дорогих решениях. Кончился — день провален.
  Остаток идёт в зачёт очков.

Таймер дня меняется полем `minutes` в `ROUNDS`, бюджет минут считается автоматически
из самих инцидентов.

Цвета ролей: менеджер оранжевый, разработчик зелёный, тестировщик голубой. Фон экрана
подкрашивается цветом роли, чей сейчас ход.

**Табло** — вертикальный дашборд: команда = строка, всё в один экран без прокрутки
(проверено до десяти команд на 1280×720). В дне команды стоят по очкам и **меняются
местами прямо во время игры**, прогресс инцидента показан точками по шагам в цвете роли
(менеджер → разработчик → тестировщик → разработчик → менеджер). На выборе модулей
видно, кто определился; на деплое — у кого модуль встал, а у кого упал и почему.
По итогам дня остаётся только лидерборд, он раскрывается снизу вверх.

**Раунды открывает и закрывает только ведущий** — у игроков кнопок управления нет.
Если ведущий закрыл вкладку, он возвращается через `/#/host` с паролем и кодом.

**Список команд ведущий правит в лобби:** «+ команда» добавляет, «убрать» удаляет
пустую, клик по названию переименовывает (Enter — сохранить, Esc — отменить).

## Запуск локально

На Windows проще всего двойной клик по **запустить.bat** — сам найдёт Node из nvm,
поставит зависимости при первом запуске, соберёт клиент, освободит порт, откроет
браузер и оставит сервер в окне (закрыть окно = остановить).

Руками: нужна Node 20.19+ (в папке `.nvmrc` с v25.9.0).

```bash
npm install
npm run serve     # собрать клиент и раздавать всё с порта 8787
```

Для разработки: `npm run dev` — клиент на 5173 с горячей перезагрузкой.
Сервер печатает адреса игроков, табло и ведущего.

## Развёртывание на VPS

### GitHub + автодеплой (основной путь)

Один раз на чистом Ubuntu (под root), подставив свой репозиторий и домен:

```bash
REPO=https://github.com/midhey/onfimgame DOMAIN=smena.example.ru bash <(curl -fsSL https://raw.githubusercontent.com/midhey/onfimgame/master/vps-setup.sh)
```

Скрипт ставит git и Node 22, клонирует репозиторий в /opt/smena, собирает клиент,
заводит службу smena, ставит Caddy с автоматическим HTTPS для домена и включает
smena-update.timer: раз в минуту сервер сверяется с GitHub — новый коммит в main
подтягивается, собирается и перезапускается сам (ветка — та, что склонирована). То есть **git push = деплой**,
никаких секретов не нужно. Пароль ведущего генерируется и печатается в конце
(и лежит в /etc/smena.env).

CI в GitHub Actions (.github/workflows/ci.yml) на каждый пуш собирает клиент и
гоняет 36 проверок сценарного теста. Если добавить секреты VPS_HOST, VPS_USER,
VPS_SSH_KEY — после зелёных тестов деплой дёргается по ssh мгновенно, не дожидаясь
таймера. Без секретов pipeline всё равно зелёный, деплоит таймер.

Без домена (просто по IP): не указывайте DOMAIN — приложение встанет на 80 порт
по http. Репозиторий должен быть публичным (или добавьте deploy key на VPS).

### Если с рабочего компьютера нет ssh на VPS

SSH на сервер не нужен вообще — есть три пути, все через браузер:

1. **Cloud-init при создании VPS.** В панели провайдера при заказе сервера есть
   поле «user data» / «cloud-init». Вставьте туда (подставив домен):

   ```yaml
   #cloud-config
   runcmd:
     - curl -fsSL https://raw.githubusercontent.com/midhey/onfimgame/master/vps-setup.sh -o /root/vps-setup.sh
     - REPO=https://github.com/midhey/onfimgame DOMAIN=smena.example.ru bash /root/vps-setup.sh
   ```

   Сервер настроит себя сам при первой загрузке. Пароль ведущего останется
   в /etc/smena.env — его покажет любой из путей ниже, либо задайте свой:
   добавьте строку `SMENA_HOST_PASS=вашпароль` перед `bash` во второй команде.

2. **Кнопка в GitHub Actions.** Добавьте секреты (см. ниже), затем
   Actions → setup-vps → Run workflow, впишите домен. Раннер GitHub сам зайдёт
   на сервер и всё поставит; адреса и пароль ведущего появятся в сводке запуска.

3. **Веб-консоль провайдера.** У любого VPS в панели есть браузерная консоль —
   вставьте туда команду установки из начала этого раздела.

### Секреты для Actions (Settings → Secrets and variables → Actions)

| Секрет | Что класть | Зачем |
|---|---|---|
| `VPS_HOST` | IP или домен сервера | setup-vps и мгновенный деплой |
| `VPS_PASSWORD` | root-пароль от провайдера (из письма/панели) | самый простой вариант входа |
| `VPS_SSH_KEY` | приватный ключ (альтернатива паролю) | если ключ удобнее |
| `VPS_USER` | необязательно, по умолчанию root | |

Секреты нужны только для кнопки setup-vps и мгновенного деплоя. Обычный деплой
работает без них: сервер сам подтягивает новые коммиты раз в минуту.

### Вручную со своей машины

Скрипт (нужен ssh-доступ; на Windows запускать из Git Bash):

```bash
./deploy.sh root@vps.example.ru
```

Скрипт заливает код в `/opt/smena`, ставит зависимости, собирает клиент, создаёт
`/etc/smena.env` (пароль ведущего генерируется и печатается — запишите), ставит
systemd-юнит `smena.service` и запускает. Повторный запуск = обновление, env не
перетирается. Свой путь: `./deploy.sh user@host /srv/smena`. Свои значения:
`SMENA_URL=https://smena.example.ru SMENA_HOST_PASS=секрет ./deploy.sh user@host`.
Уже на сервере — `./deploy.sh --local` из папки приложения.
Вручную — никакой базы, один процесс Node:

```bash
npm install
npm run build
SMENA_HOST_PASS=вашпароль PORT=8787 node server/src/index.js
```

Полезные переменные: `PORT` (по умолчанию 8787), `SMENA_HOST_PASS` (пароль ведущего),
`SMENA_URL` (публичный адрес, который показывается на табло и экране ведущего,
например `https://smena.example.ru` — без него сервер покажет локальный IP).

Пример systemd-юнита:

```ini
[Unit]
Description=Smena game
After=network.target

[Service]
WorkingDirectory=/opt/smena
Environment=PORT=8787
Environment=SMENA_HOST_PASS=вашпароль
Environment=SMENA_URL=https://smena.example.ru
ExecStart=/usr/bin/node server/src/index.js
Restart=always

[Install]
WantedBy=multi-user.target
```

Если ставите nginx перед сервером — не забудьте проксировать вебсокет `/ws`
(заголовки `Upgrade`/`Connection`). Состояние живёт в памяти: перезапуск процесса
завершает идущие занятия.

## Где править тексты

Всё в одном файле: [`server/src/data.js`](server/src/data.js).

- `ROUNDS` — дни недели: `title`, `minutes` (реальный таймер), `perTeam` (сколько
  инцидентов достаётся одной команде) и `pool` — пул инцидентов дня. Разминка — день
  с `trial: true`;
- команды: ведущий добавляет («+ команда») и убирает («убрать» на пустой команде) прямо в лобби;
- инцидент: `manager` → `engineer` → `tester` → `engineerFix` (доработка по замечаниям)
  → `managerClose` (закрытие перед бизнесом), везде по **три** варианта (`label`,
  `result`, `time`, `trust`); у менеджера ещё `ticket` у каждого варианта и
  `asks: true` ровно у одного; `truth` — «на самом деле»; `module` — что уходит
  в продакшн; `flaw` — изъян слабого варианта у `tester` и `engineerFix` (в каждом
  из этих шагов ровно один вариант без изъяна);
- `NOISE` — карточки шума между инцидентами;
- `TEAM_NAMES` — названия команд (нейтральные, по животным);
- `RULES` — доверие, штрафы и веса очков.

Файл собирается скриптом: `node scripts/build-data.mjs` берёт инциденты, дописывает
модули и изъяны из таблицы в самом скрипте, подмешивает `scripts/new-incidents.json`
и пересчитывает бюджеты минут. Правите тексты руками — просто больше не запускайте
скрипт, data.js самодостаточен.

## Проверка

```bash
node scripts/selftest.js
```

36 проверок на реальных вебсокетах: пароль ведущего, права ведущего на старт, деплой
и раунды, жёсткие роли, круг разработки (порядок шагов), разные инциденты у разных
команд, модули без показа изъяна, выбор модуля только менеджером, деплой со штрафом
доверия, общие очки, границы доверия, неделя целиком до итогов, редактирование команд,
сброс. Сервер должен быть запущен; пароль — из `SMENA_HOST_PASS`.

## Структура

```
server/src/data.js    все тексты: раунды, инциденты, варианты, шум
server/src/game.js    правила команды: ходы, лента, бюджет, рейтинг
server/src/room.js    занятие: игроки, команды, фазы, таймер, логи, табло
server/src/index.js   http + вебсокеты + тикер таймера
client/src/store.js   соединение, hash-роутер, тик таймера
client/src/views/     Join, Lobby, Round, Rating, Final, HostAuth, Host, Board
```

Клиент ничего не считает: сервер присылает каждому свой снимок, включая варианты —
вариантов чужой роли в снимке просто нет.

## Известные ограничения

- состояние в памяти процесса: перезапуск сервера завершает занятия;
- пароль ведущего один на всех и передаётся открытым текстом — ставьте https
  на VPS и не используйте ценный пароль;
- ведущий одновременно один; пока он на связи, раундами управляет только он;
- в одном браузере одна личность: две вкладки делят память, ведущего и игрока
  одновременно в одном браузере не подержать (на разных устройствах — без ограничений).
